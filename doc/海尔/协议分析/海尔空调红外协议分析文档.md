# 海尔空调红外协议分析文档

## 1. 协议概述

本协议用于海尔空调遥控器与空调主机之间的红外通信。数据通过脉冲宽度调制编码，  
每个 bit 由一对脉冲宽度表示。

### 1.1 脉冲编码规则

|逻辑值|脉冲编码 (学习码)|脉冲编码 (自组码)|
| --------| -------------------| -------------------|
|1|​`xx FE xx FA` (长脉冲)|​`33 FE D0 FA`|
|0|​`xx FE xx FE` (短脉冲)|​`1E FE 58 FE`|

- 每个 bit 占 4 字节脉冲宽度
- 位序：MSB（高位在前）
- 学习码从实物遥控器获取，脉冲幅度(`xx`)随遥控器不同而变化
- 自组码为手动构造，使用固定脉冲幅度

### 1.2 报文结构

```
┌──────────┬──────────────────────────────────────────────┐
│ 组成部分  │ 内容                                        │
├──────────┼──────────────────────────────────────────────┤
│ 前导码   │ XX F6 XX F6 XX F6 XX F2  (8字节)            │
│ 数据段   │ 16字节 (含起始码、控制数据、校验、B7标记)     │
│ 结束码   │ 87 FE                                         │
│ 补位码   │ FF FF ... (补齐到1024字节)                   │
└──────────┴──────────────────────────────────────────────┘
```

## 3. 字段详解

### 3.1 温度编码 (Byte1[7:4])

温度值 = Byte1[7:4] + 16

|温度|编码|温度|编码|温度|编码|
| -------| ------| -------| ------| -------| ------|
|16°C|0x0|21°C|0x5|26°C|0xA|
|17°C|0x1|22°C|0x6|27°C|0xB|
|18°C|0x2|23°C|0x7|28°C|0xC|
|19°C|0x3|24°C|0x8|29°C|0xD|
|20°C|0x4|25°C|0x9|30°C|0xE|

### 3.2 运行模式 (Byte7)

|值|模式|说明|
| ------| ------| ------------|
|0x20|制冷|Cooling|
|0x80|制热|Heating|
|0x40|除湿|Dehumidify|
|0xC0|自动|Auto|
|0x60|送风|Fan only|

### 3.3 开关与辅热 (Byte4)

|Bit|功能|说明|
| -----| ------| ------------------------|
|[7]|辅热|1=开启辅热, 0=关闭辅热|
|[6]|开关|1=开机, 0=关机|

常见组合：

- ​`0x40` = 开机、无辅热
- ​`0xC0` = 开机、有辅热
- ​`0x00` = 关机

### 3.4 按键码 (Byte12)

学习码与自组码的按键码定义不同：

#### 自组码按键码 (报文记录)

|值|按键|
| ------| ---------------|
|0x05|开/关机|
|0x01|温度调节/其他|

#### 学习码按键码

|值|含义|
| -----------| -----------------------|
|0x00~0x06|各通道/按键对应的标识|
|0x0D|制冷 Ch2|
|0x13|haier Ch1/Ch8|
|0x17|haier Ch2/Ch4|
|0x21|haier Ch5/Ch6|
|0x27|制热 Ch1|
|0x31|制热 Ch2|
|0x3D|制冷 Ch5|

### 3.5 校验和

自组码校验算法：

```
Checksum = (Byte0 + Byte1 + ... + Byte12) & 0xFF
```

验证示例：

- 制热30度: A6 + E6 + 00 + 00 + 40 + A0 + 40 + 80 + 00 + 00 + 00 + 00 + 05 = 0331 → 校验 = 31 ✓
- 制热21度: A6 + 56 + 00 + 00 + 40 + A0 + 40 + 80 + 00 + 00 + 00 + 00 + 01 = 029D → 校验 = 9D ✓
- 制冷20度: A6 + 46 + 00 + 00 + 40 + A0 + 40 + 20 + 00 + 00 + 00 + 00 + 05 = 0231 → 校验 = 31 ✓
- 制冷25度: A6 + 96 + 00 + 00 + 40 + A0 + 40 + 20 + 00 + 00 + 00 + 00 + 01 = 027D → 校验 = 7D ✓
- 关机: A6 + 96 + 00 + 00 + 00 + A0 + 40 + 20 + 00 + 00 + 00 + 00 + 01 = 023D → 校验 = 3D ✓

学习码校验算法：与自组码不同，学习码使用特殊校验方式，待进一步分析。

## 6. 总结

### 一致的部分

- 起始码 `A6`
- 温度编码方式 `[7:4] = 温度 - 16`
- 模式字节 `20=制冷 80=制热 40=除湿`
- 开关/辅热位定义 `[7]=辅热 [6]=开关`
- B7 固定标记
- 基本报文框架（前导+数据+结束）

### 存在差异的部分

1. Byte6：自组码固定为 `40`​，学习码固定为 `00`
2. 校验算法：自组码使用简单求和，学习码使用不同算法
3. 按键码值：自组码与学习码的按键编码不同
4. 前导码：自组码固定 `52 F6 8B F6 64 F6 44 F2`，学习码各通道不同
5. 脉冲幅度：自组码固定 `33FE/1EFE`，学习码幅度随遥控器变化

### 结论

学习码与自组码基于**同一协议**，核心字段（起始码、温度、模式、开关、B7标记）  
的编码方式和位置完全一致。差异主要体现在：

- 自组码是简化构造版本，部分字段有固定填充值（如 Byte6=40）
- 学习码是完整遥控器学习数据，保留了更多实际状态信息
- 两者在实际使用中可以互相参考，但校验和按键码需要分别处理
