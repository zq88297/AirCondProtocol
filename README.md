# 空调红外协议自动分析工具

这个仓库提供一个跨平台的 `Python 3.11+` 命令行工具，用来分析 `doc/<品牌>/报文` 下的红外学习报文，并输出：

- `自动协议分析.md`
- `报文分解.tsv`

默认输出目录是 `doc/<品牌>/协议分析/`。

## 源码位置

```text
src/
  __init__.py
  ac_ir_tool/
    __init__.py
    __main__.py
    cli.py
    core.py
```

## 运行前提

- 需要安装 `Python 3.11+`
- 工具只使用 Python 标准库，不依赖第三方包

## 运行方式

```bash
python -m src.ac_ir_tool analyze --brand-dir doc/格力
```

可选参数：

```bash
python -m src.ac_ir_tool analyze \
  --brand-dir doc/格力 \
  --output-dir doc/格力/协议分析 \
  --manifest doc/格力/报文/样本清单.json \
  --legacy-description doc/格力/报文/报文说明.txt
```

## 目录约定

每个品牌目录固定为：

```text
doc/<品牌>/
  报文/
  协议分析/
```

其中：

- `报文/` 放原始学习报文和说明
- `协议分析/` 放工具生成结果

## 推荐输入方式

现在不再强制要求你先手工准备 3 个报文文档。

推荐直接提供：

- 一个或多个原始报文 `.txt`
- 一个 `报文说明.txt`

只要 `报文说明.txt` 里写明每条 `LearnNCode` 对应的模式或动作，程序就会自动：

1. 读取原始 `LearnNCode=<HEX>`
2. 根据 `报文说明.txt` 和解码出的模式信息归类
3. 自动拆分出 3 组样本
4. 在内存中按这 3 组样本继续分析
5. 最终只输出协议分析结果文件

### 报文说明写法

支持这种写法：

```text
Learn1Code是开机制冷、Learn2Code是开机制热、Learn3Code是关机，
Learn4Code是制冷降温，Learn5Code是制冷升温，
Learn7Code-Learn11Code是制热升温，
Learn27Code、Learn29Code是关机，
Learn28Code、Learn30Code是开机。
```

支持：

- 单条：`Learn1Code是开机制冷`
- 范围：`Learn7Code-Learn11Code是制热升温`
- 列表：`Learn27Code、Learn29Code是关机`

### 自动拆分规则

- `制冷样本`：解码后模式为制冷的报文
- `制热样本`：解码后模式为制热的报文
- `冷暖开关机样本`：说明中带 `开机` / `关机`，或解码后模式为关机的报文

注意：

- 同一条报文可以同时属于多个自动分组
- 例如 `开机制冷` 会同时进入 `制冷样本` 和 `冷暖开关机样本`

## 标准样本清单模式

如果你已经手工整理好了样本，也仍然支持结构化清单 `报文/样本清单.json`。

格式示例：

```json
{
  "samples": {
    "cool": {
      "file": "报文/制冷样本.txt",
      "description": "制冷场景",
      "learn_map": {
        "cool_on": "Learn1Code",
        "cool_temp_up": "Learn2Code"
      }
    },
    "heat": {
      "file": "报文/制热样本.txt",
      "description": "制热场景"
    },
    "power_cycle": {
      "file": "报文/冷暖开关机样本.txt",
      "description": "冷暖模式开关机场景"
    }
  }
}
```

在 `manifest` 模式下，当前仍要求这 3 组都存在：

- `cool`
- `heat`
- `power_cycle`

也就是说：

- `manifest` 模式是“你已经整理好分组”
- `legacy + 报文说明` 模式是“程序替你自动分组”

## 原始报文文件要求

原始报文文件至少包含这类记录：

```text
[KT-LearnCode]
Learn1Code=93E30DF2...
```

工具会自动：

- 去掉 `0100` 终止符之后的内容
- 去掉尾部 `FF` 填充
- 自动跳过全 `FF` 或裁剪后为空的无效 `Learn` 报文
- 按帧拆分脉冲对
- 解码为 bit 流和字节流
- 输出保守推导结果

## 输出说明

### 自动协议分析.md

包含：

- 输入样本概览
- 原始编码观察
- 两帧 payload 结构
- 字段推导表
- 未解字段说明

字段状态：

- `已确认`：固定字段，或与标签有稳定映射
- `推测`：变化规律明显，但证据还不够
- `未知`：当前样本不足以安全命名

### 报文分解.tsv

固定列：

- `样本`
- `Learn`
- `段名`
- `原始脉冲`
- `二进制`
- `十六进制`
- `位说明/字段说明`

设计目标是方便直接粘贴到后续的报文记录表格中。

## 格力当前用法

格力现在既可以用手工样本清单，也可以只保留：

- 原始报文文件
- `报文说明.txt`

程序会在分析时自动生成拆分后的三个样本文件，再继续分析。
程序会在分析时自动完成三组归类，但不会额外落盘样本文本，只保留最终的 `自动协议分析.md` 和 `报文分解.tsv`。

## 后续品牌建议

后续品牌建议至少保证以下两点：

- 原始报文文件里有完整的 `LearnNCode=<HEX>`
- `报文说明.txt` 能明确写出每条报文对应的模式或动作

这样即使不手工整理成 3 个文档，程序也可以自动拆分并继续分析。
